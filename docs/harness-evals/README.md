# Harness verification

Run `node scripts/harness/verify.mjs --base <confirmed-task-ref>` at repository root after `npm ci` in frontend. Optional first argument selects `scripts`, `backend`, `frontend`, or `browser`; the report states the selected scope. A scope PASS does not certify the other groups. Scripts/all require an explicit task base for migration comparison; missing base is BLOCKED, never guessed as main. The current task base is afb8f8b58f0be9846b470409bff6fa4e22eba8b5.

Requirements: Node/npm, JDK/Maven wrapper; Docker for backend PostgreSQL and browser groups; Playwright Chromium installed for browser. Git Bash on Windows enables the four shell workflow tests (otherwise Node reports their skips). Default checks remove every `RUN_LIVE_*` opt-in, including lowercase keys on Windows, and set `CI=true`. They use synthetic fixtures, H2/Postgres Testcontainers, and fake AI, never Supabase production or live AI.

Exit codes: 0 PASS, 1 FAIL, 2 BLOCKED. Later steps after a failure are SKIPPED. Missing Docker blocks its groups. No result is promoted to PASS because a test was skipped. Opt-in LiveTest classes remain intentionally disabled and their counts are visible in surefire logs.

Each run writes a fresh directory under `backend/target/harness-evidence/`, with command logs (credentials redacted) and report.json containing exact commands, exit codes, log SHA-256 and source commit/content hash before and after. Source changed during verification is FAIL. `node scripts/harness/verify.mjs --check-report <report.json>` checks all required steps, intact logs and the current source, including staged/unstaged/untracked nonignored files. Even changing completion documentation requires a new receipt. This detects stale/accidentally modified evidence; it is not a signed attestation against a malicious author. Evidence is ignored by git; retain HTTP artifacts for 14 days and browser artifacts for 7 days in CI. Never run this against teacher data or publish raw credentials.

Only the latest verification attempt can supply an accepted receipt. Its pointer is written before preflight/checks, so a later FAIL/BLOCKED/interruption prevents reusing an older green report even when source is unchanged. Starting any group supersedes older receipts, including an older all-group report; rerun all after final changes for an all-group handoff. Completion never rewrites the pointer, so an older concurrent run cannot replace a newer attempt.

All script tests are included, including the two formerly excluded SRS suites. Repository checks also cover AI-log format/rotation, migration rules against the explicit base, OpenAPI index, agent fixture validity and adapter drift/orphans. Secret scanning remains the existing gitleaks Git/CI gate, separately reported for this uncommitted delivery.
